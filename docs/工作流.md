# Data Video Dataset 工作流

当前基于网页标注的 multichart v2 数据集的规范工作流：

- 网页中的 `reference_start/reference_end` 区间是视觉片段边界的唯一依据。
- `context.mp4` 在网页区间前后各扩展 5 秒，仅用于提取完整旁白。
- Qwen2.5-VL 仅用于处理 `visual_clip.mp4` 或由其提取的帧的视觉任务。
- 当前网页标注数据不使用 Qwen 重新检测图表边界。
- 完整旁白可能在视觉片段之前开始或之后结束，但不能因此扩展 `visual_clip.mp4`。
- 后续动画与旁白的对齐使用源视频时间坐标。


## 时间坐标

所有时间值均以秒为单位。

- `reference_source`：源视频时间中的网页视觉区间，是权威区间。
- `context_source`：用于生成 `context.mp4` 的源视频区间。
- `visual_clip_context`：`context.mp4` 内的视觉片段区间。
- `visual_clip_relative`：`visual_clip.mp4` 内的视觉片段区间，始终从 `0.0` 开始。
- 完整旁白句子的时间使用源视频/上下文坐标，可能超出视觉片段范围。
- 视觉字幕使用相对于视觉片段的坐标，必须位于 `[0, visual_clip_duration]` 内。

上下文填充：

```yaml
context:
  padding_before_seconds: 5.0
  padding_after_seconds: 5.0
```

计算公式：

```text
context_start = max(0, reference_start - 5.0)
context_end = min(source_duration, reference_end + 5.0)
visual_start_in_context = reference_start - context_start
visual_end_in_context = reference_end - context_start
```

## 动态数据恢复

`dynamic_data.json` 和 `dynamic_data.csv` 是机器恢复的数据状态主产物。`final_data_table.csv` 保存每个实体最新已知数值或定性事实，`data_change_events.csv` 保存 insert/update/remove 事件，`chart_data.csv` 保留为审核表格兼容视图，`data_events.jsonl` 则镜像变化事件，供后续动画生成工具读取。

每条动态状态记录包含：

```text
clip_id,state_id,entity_id,metric,value,unit,state_start,state_end,
source_type,evidence_frames,evidence_sentence_id,confidence,review_status
```

恢复顺序以视觉片段优先。Qwen 只恢复 evidence frame 中明确打印的数值；没有打印值或可靠标尺时，不能把柱长、折线位置等几何长度当成真实值。如果视觉中没有可恢复数值，仍必须继续执行 narration 恢复：完整旁白句子与 visual clip 重叠或明确对应该动画事件，并且包含实体、数值和单位时，可作为 exact 数值事实。支持英文数词，例如 `two full days -> 2 day`。只要至少存在一个可靠数值，该 clip 可以 `data_completeness=partial` 纳入；缺失实体保留为 qualitative/null。如果视觉和对应旁白都没有可验证数值，该 clip 以 `exclude_reason=no_recoverable_quantitative_data` 排除。

视觉和旁白按稳定身份融合。数值一致时标记 `source_type=both`；冲突时保留双方证据并设置 `review_status=needs_review`。旁白只说增加/减少但没有数字时，不生成数值数据行。`a lot of time` 这类定性旁白可保留为 partial 的非数值实体事实。

抽帧是两阶段：保留 2 FPS 粗扫描，用低成本的画面/图表区域/OCR 数字变化信号定位疑似数据变化窗口，只在窗口内抽 8 FPS state/evidence frames；若窗口内仍不足，再使用源视频帧率兜底。Qwen 只处理筛选后的代表帧，不遍历所有高帧率帧。

状态合并只在时间局部发生：仅合并连续且实体集合和值签名相同的记录，并保留 `state_start`、`state_end` 和证据。`A -> A -> B -> B -> A` 会保留为 `A`、`B`、`A` 三段；纯动画插值但打印数据不变时只保留一个状态。实体新增记为 `insert`，数值改变记为 `update`，实体消失记为 `remove`。

## 质量检查

当关键帧、数据表、semantic SVG、动画检测和旁白都生成后，运行质检生成待人工复核队列：

```bash
python -m datavideo.cli quality-check --config configs/multichart_assets_v2.yaml
```

质检分三层：

1. Python 规则检查：必需文件、JSON/CSV schema、include/exclude 一致性、状态数量、事件一致性。
2. Python 跨产物检查：`dynamic_data` 里的实体 ID 与 `semantic.svg`、状态级 semantic SVG 是否能对应。
3. 可选 VLM 视觉检查：查看关键帧、semantic preview、动态数据摘要、动画检测和旁白证据，标记疑似漏识别或错读。

质检模型独立配置在 `quality.model`，可以和生产模型使用不同 provider。`quality.enable_vlm=false` 时只运行确定性的 Python 检查。输出为：

```text
data/generated/quality/quality_report.json
data/generated/quality/quality_flags.csv
data/generated/quality/quality_review_queue.csv
```

## 区间

`data/processed/<clip_id>/intervals.json` 只存储机器生成的源数据事实：

```json
{
  "time_unit": "seconds",
  "reference_source": {"start": 65.0, "end": 77.0},
  "context_source": {"start": 60.0, "end": 82.0},
  "visual_clip_context": {"start": 5.0, "end": 17.0},
  "visual_clip_relative": {"start": 0.0, "end": 12.0},
  "requires_context_redownload": false
}
```

不要将旁白完整区间写成视觉片段边界。当前规范区间不包含 `chart_context`、`chart_source`、`proposed_clip_context`、`proposed_clip_source`、`reviewed_clip_context` 或 `reviewed_clip_source`。

如果无法下载真正的上下文，流程回退到精确的网页片段，则设置：

```json
"requires_context_redownload": true
```

这不会阻止视觉资源生成，只表示完整旁白不完整，不能伪造完整旁白。

## 2. 上下文与视觉片段

生成上下文媒体、上下文音频和严格的视觉片段：

```bash
PYTHONPATH=src python -m datavideo.cli context \
  --config configs/multichart_assets_v2.yaml
```

单个片段：

```bash
PYTHONPATH=src python -m datavideo.cli context \
  --config configs/multichart_assets_v2.yaml \
  --clip-id bar_1
```

在可能的情况下，`visual_clip.mp4` 从 `context.mp4` 中生成：

```text
visual_clip.mp4 = context.mp4[visual_start_in_context:visual_end_in_context]
```

视觉片段时长应与 `reference_end - reference_start` 一致，允许正常编码误差。`visual_clip_report.json` 会记录预期时长、ffprobe 时长和时长误差。

## 3. 上下文 ASR 与完整旁白

仅对上下文音频运行 ASR：

```bash
PYTHONPATH=src \
WHISPER_MODEL_PATH=/path/to/faster-whisper-model \
python -m datavideo.cli asr \
  --config configs/multichart_assets_v2.yaml
```

输入：

```text
data/processed/<clip_id>/context_audio_16k_mono.wav
```

选择规则：

- 选择实际与 `reference_source` 重叠的句子。
- 保留所选句子的完整源视频/上下文时间，即使句子在视觉片段前开始或后结束。
- 不添加与 `reference_source` 不重叠的相邻句子。
- 使用标点、Whisper 片段、词级时间戳和清晰停顿推断句子边界。
- 对低置信度或边界模糊、处于上下文边缘的结果标记 `needs_review`。
- 如果 `requires_context_redownload=true`，将旁白状态设为 `incomplete_context`。
- 不要将片段外的完整句子时间转换成虚假的视觉字幕时间。

输出：

```text
selected_full_sentences.jsonl  # 完整的源视频/上下文句子区间
overlap_words.jsonl            # 仅包含与视觉片段重叠的词
subtitles.srt                  # 相对于视觉片段、且限制在片段时长内
transcript_provenance.json
```

## 4. 视觉资源

从严格的视觉片段生成关键帧、semantic SVG 和图表数据：

```bash
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1 \
PYTHONPATH=src \
MODEL_PATH=/path/to/qwen-vl-model \
python -m datavideo.cli assets \
  --config configs/multichart_assets_v2.yaml
```

`assets` 读取：

```text
data/processed/<clip_id>/visual_clip.mp4
```

它会将 `data/generated/<clip_id>/clip.mp4` 写为用于审核的视觉片段，然后生成：

- 来自视觉片段帧的候选关键帧；
- Qwen 关键帧评分；
- `keyframes/initial.png`；
- 可选的 `keyframes/states/state_*.png`；
- Qwen 对整段 clip 生成的、与目标图表相关的整体动画描述；
- 可选的主要目标图表动画动作及其证据时间戳；
- `semantic.svg` 和 `semantic_preview.png`；
- 基于视觉片段帧序列恢复的图表数据。

动画检测规则：

```text
仅使用从 processed/<clip_id>/visual_frames 中采样的、属于严格视觉片段的帧。
以 `animation.sample_fps` 对完整视觉片段采样，并让 Qwen 在一次调用中观察有序帧。
Qwen 必须为与目标图表类型相关的动画生成一句简洁中文 `overall_description`。
`major_actions` 可以为空，也可以包含任意数量的真实独立动作；不要为了填满数量而拆分。
只有与目标图表相关的动作才进入 `major_actions`。
```

规范配置：

```yaml
animation:
  sample_fps: 2
  types:
    - no_clear_animation
    - bar_grow
    - bar_shrink
    - line_draw_upward
    - line_draw_downward
    - pie_or_donut_segments_appear
    - map_region_highlight
    - chart_type_transition
    - element_appear
    - element_disappear
    - element_highlight
    - other
  purpose: one-sentence overall target-chart animation description from the complete visual clip
```

目标相关性：

```text
只检测与目标图表类型相关，或发生在目标图表内部的动画。
相关动画包括：
1. 目标图表内部的变化；
2. 直接影响目标图表数据元素、坐标轴、图例、标签或注释的变化；
3. 目标图表整体出现、消失或被高亮；
4. 目标图表是起始状态或结束状态的图表类型转换。

忽略普通字幕、标志、人、背景、装饰元素、不相关的图表类型以及非目标图表的变化。
```

整段一致性约束：

```text
对于 bar_grow、bar_shrink、line_draw_upward 和 line_draw_downward 等数据元素动画类型，
证据时间戳必须指向同一个目标图表场景。
不要将从非图表/装饰性的刻度或标题场景进入目标图表的转换当作数据元素增长或折线绘制。
只有当该跨场景变化明确表示目标图表整体出现，或表示目标图表为起始/结束状态的图表类型转换时，才可以保留。
```

动作连续性与合并规则：

```text
作用于同一目标图表对象、方向相同且视觉状态连续的变化，属于一个完整主要动作。
不要因为速度变化、缓动、短暂停顿或某一帧变化幅度较低，就拆分同一个柱形增长/收缩或折线上升/下降。

只有在以下情况才拆分：
1. 动画方向反转；
2. 目标对象明显改变；
3. 动画类型改变；
4. 中间出现明确的稳定状态或另一个独立动画。
```

规范的粗粒度动画类型：

```text
no_clear_animation
bar_grow
bar_shrink
line_draw_upward
line_draw_downward
pie_or_donut_segments_appear
map_region_highlight
chart_type_transition
element_appear
element_disappear
element_highlight
other
```

动画输出：

```text
animation_detection_raw.json       # Qwen 原始响应和来源信息
animation_detection.json           # 规范化后的机器动画结果
```

`animation_detection.json` 必须使用以下整段 clip 结构：

```json
{
  "clip_id": "bar_1",
  "target_chart_type": "bar",
  "sample_fps": 2,
  "frame_count": 18,
  "visual_start": 0.0,
  "visual_end": 9.0,
  "is_target_chart_related": true,
  "overall_description": "目标柱状图中的蓝色柱子持续下降，随后数值标签出现。",
  "major_actions": [
    {
      "action": "bar_shrink",
      "description": "蓝色柱子持续下降。",
      "evidence_timestamps": [1.0, 2.5, 4.0]
    },
    {
      "action": "element_appear",
      "description": "柱子上方的数值标签出现。",
      "evidence_timestamps": [6.5, 7.5]
    }
  ],
  "confidence": 0.88
}
```

如果未检测到明显动画：

```json
{
  "is_target_chart_related": false,
  "overall_description": "没有检测到与目标图表相关的动画。",
  "major_actions": [],
  "confidence": 0.0
}
```

`multichart_v2_clips.jsonl` 也会暴露便于检索和审核的 clip 级字段：

```text
animation_description       # 来自 animation_detection.overall_description
animation_action_count
animation_confidence
is_target_chart_related
```

图表数据规则：

```text
只恢复帧中直接打印出来的数值，不要根据几何形状估算数值。
```

## Qwen 输入规则

允许的 Qwen 输入：

- `data/processed/<clip_id>/visual_frames/...`；
- `data/generated/<clip_id>/keyframes/...`；
- 从 `visual_clip.mp4` 派生的帧或静态图像。

禁止的 Qwen 输入：

- `context.mp4`；
- 从上下文提取的帧；
- 上下文边界帧；
- 网页 reference 区间之外的任何帧；
- `context_audio_16k_mono.wav`。

v2 资源代码会验证 Qwen 图像路径，并在关键帧/数据报告中记录所有输入帧路径。

## 5. 人工审核

规范的视觉审核页面：

```bash
PYTHONPATH=src streamlit run app/multichart_v2_review_app.py
```

该页面审核：

- 视觉片段；
- 选定的关键帧和状态帧；
- 动画整体描述和可选的主要动作表；
- 旁白句子及可编辑的人工审核旁白文本；
- PNG/SVG 语义图输出；
- 恢复的图表数据；
- 资源决策。

新的审核记录使用英文决策值：

```text
approved        -> 进入最终视觉数据集
needs_revision  -> 阻止进入最终数据集
saved           -> 仅保存为草稿
excluded        -> 进入排除列表
```

进入最终视觉数据集的条件：

```text
asset_review.decision == "approved"
```

同一资源审核记录会在 `reviewed_value.animation` 下保存人工审核的动画字段，其中包含 `overall_description`、`major_actions` 和 `confidence`。机器动画仍保存在 `data/generated/<clip_id>/animation_detection.json`；人工审核后的动画由 `reviewed` 写入 `animation_reviewed.json`。

同一资源审核记录也会在 `reviewed_value.narration` 下保存人工审核后的旁白。审核者可以编辑句子文本，也可以取消 `keep_in_reviewed`，让某句不进入最终数据集。机器 ASR 会继续复制用于审计；人工审核后的旁白会写入 `narration_reviewed.json`。

## 已弃用的边界审核

片段边界审核 UI 不再属于网页标注数据的规范工作流。当前权威的视觉边界是网页上的 `reference_start/reference_end` 区间，因此片段边界审核只保留给旧记录，不应用于生成新的官方输出。

## 6. 已审核数据集

重新构建已审核输出：

```bash
PYTHONPATH=src python -m datavideo.cli reviewed \
  --config configs/multichart_assets_v2.yaml
```

该命令读取 `data/review/review.db` 中最新的资源审核结果，并将最终审核产物写入 `data/reviewed/datavideo_multichart_v2`。

它不需要也不会应用旧的片段边界审核结果。最终的 `clip.mp4` 从 `data/generated/<clip_id>/clip.mp4` 复制，该文件对应网页 reference 区间。

人工审核后的动画会从已批准的资源审核值复制到 `animation_reviewed.json`；机器原始报告也会被复制以供审计。`clip.json` 和 `final_multichart_v2_clips.jsonl` 会暴露 `animation_description`，便于筛选和检查。

有可用的处理后 ASR 输出时，会复制以下旁白文件：

- `selected_full_sentences.jsonl`；
- `overlap_words.jsonl`；
- `subtitles.srt`；
- `transcript_provenance.json`；
- `narration_status.json`。

人工审核后的旁白会写入：

- `narration_reviewed.json`；
- `narration/narration_reviewed.json`。

## 缓存失效

- reference/context 区间变化：重新生成上下文、视觉片段和 ASR。
- 视觉片段变化：重新生成关键帧、动画检测、SVG 和图表数据。
- ASR 模型或上下文音频变化：重新生成旁白。
- 人工旁白编辑：不要重新运行 ASR。
- 旁白编辑：不要重新生成视觉资源。
